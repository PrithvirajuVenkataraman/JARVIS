# GitHub upload and Vercel Hobby deployment

Commit the source project to GitHub. Vercel installs the locked dependencies and builds the frontend; do not upload a hand-picked subset of compiled files.

Preserve directory names and include dotfiles when using GitHub's upload interface. Git is preferable because the same commit can record removed files; uploading replacements through the website does not delete old repository files automatically.

After reviewing the changes locally:

```sh
git status --short
git add -A
git diff --cached --stat
git diff --cached --check
git commit -m "Modernize JARVIS reliability and deployment"
git push
```

Review the staged file list before committing. Existing obsolete files must be deleted in the same commit, including the old duplicate `public/katex-*` assets.

The current source also includes the permission, location, clipboard, settings, and local-recall modules under `app/`, their worker assets generated by Vite, and the answer visibility/preferences/arithmetic helpers under `api/_lib/`. Upload the entire source version with its matching package files; replacing only `index.html` will not update this modular application. Keep generated worker/WASM files in `dist/` out of GitHub: Vercel builds them from the locked dependencies.

## Files to leave out

- `node_modules/`, `dist/`, `build/`, `generated-tailwind.css`: installed or generated locally and on Vercel.
- `scratch/`, logs, screenshots, browser traces, reports, coverage, and incremental compiler caches: regenerated by checks.
- `.env` and all populated `.env.*` files, private keys, certificates, credentials, local agent state, and `.vercel/`: machine-specific or secret.
- The `.git/` directory when uploading through the GitHub website: Git manages it locally.

These patterns are in `.gitignore`. An ignore rule does not remove a file already committed to Git history. Never put real credentials in `.env.example`; configure them in Vercel's Environment Variables settings.

## Vercel Hobby settings

Connect the GitHub repository to a personal Vercel project with the repository root as Root Directory. Use the **Other** framework preset so the existing Node `/api/*.js` routes and explicit `vercel.json` configuration remain authoritative.

| Setting | Value |
| --- | --- |
| Node.js | `22.x` (local/CI pin: `22.23.4`) |
| Install command | `npm ci` |
| Build command | `npm run build` |
| Output directory | `dist` |
| Fluid compute | Enabled |
| Function maximum duration | Project explicitly caps requests at 60 seconds; chat/research/vision cancel work after 52 seconds |

There are seven API entry points: chat, diagnostics, image proxy, attachment ingestion, search, speech transcription, and vision. Keep `_lib` as a library directory. Compatibility rewrites route the smaller helper endpoints through diagnostics. No cron jobs, paid compute options, or new hosted services are configured. `.vercelignore` excludes development artifacts from deployment uploads, and function `excludeFiles` keeps them out of server bundles. Shared modules under `app/` are retained because the server imports some of them.

Start with only the provider credentials you need. Search defaults to disabled in `.env.example`; enable `LIVE_RETRIEVAL_ENABLED` and `WEB_SEARCH_ENABLED` when desired. Keep `JARVIS_IMAGE_FREE_TIER_ENABLED=false` unless you have verified a free allowance for that backend. Saved BYOK requires a stable matching RSA keypair configured on Vercel. Do not put any server key in a `VITE_*` variable, which can expose it to the frontend.

Hobby is intended for personal, non-commercial use. Its included usage is finite; exceeding a quota can pause a feature until its allowance resets. Vercel hosting does not make external AI providers free. Review both the [Hobby quotas](https://vercel.com/docs/plans/hobby) and [fair-use terms](https://vercel.com/docs/limits/fair-use-guidelines). The 60-second function cap remains below the current [Hobby Fluid compute duration limit](https://vercel.com/docs/functions/limitations).

## If deployment fails during `npm ci`

An `EUSAGE` error saying a lockfile is required means the deployment root has no usable `package-lock.json`. Upload the current **`package.json` and `package-lock.json` together at the repository root**, with the matching source/configuration files. The updated `package.json` includes the Vite build script and dependencies; an old package file cannot build this version of the app. Keep the install command as `npm ci`.

Check GitHub's deployed branch, not just the files on your computer. A local file marked `??` by `git status` has not been added to Git. Also verify that Vercel's Root Directory is the directory containing both package files and `vite.config.js`. After committing/uploading the complete source, deploy that new commit.

The Node engine warning in Vercel's logs is separate from a missing-lockfile error: the package engine selects Node 22.x. Set Node 22.x in project settings too. A deployment is not verified until its build actually succeeds.

## Image formats and free image creation

Commit `app/image-decoder*.js`, `app/horde-client.js`, and both package files together. Vite bundles the pinned ImageMagick WASM dependency locally, including its upstream license and third-party notices as `image-decoder-LICENSE.txt` and `image-decoder-NOTICE.txt`. Its approximately 15 MB decoder is lazy-loaded for uncommon images and excluded from the startup precache; ordinary PNG/JPEG uploads use the native browser path. RAW conversion runs on the device and does not increase Vercel Function upload limits.

Image creation submits and polls the anonymous AI Horde community queue directly from the browser. Individual network operations time out after 15 seconds; a queued job is canceled after at most ten minutes or when Stop is pressed. No Gemini image API, Puter credits, or paid fallback is used, and no Vercel Function stays open while a job queues. `JARVIS_IMAGE_GENERATION_ENABLED=false` disables the entry points; an existing `JARVIS_IMAGE_FREE_TIER_ENABLED=false` setting also disables them until removed or updated. The old `/api/image-proxy` returns an upgrade message for stale clients rather than making billed requests.

`npm run test:multimodal` includes real codec conversions and mocked free-provider success, quota, validation, and cancellation tests. For optional Nikon NEF and HEIC integration samples, run `node tools/fetch-image-test-samples.mjs`, then rerun multimodal and browser tests. Downloads remain in ignored `scratch/image-fixtures/`, with their SHA256 checksums printed; they are not committed or deployed. Without those samples, integration cases explicitly skip while generated raster fixtures still run. `JARVIS_RAW_TEST_FILE` and `JARVIS_HEIC_TEST_FILE` can point to your own samples.

## Public-site security configuration

The production site remains public. CORS restricts browser origins; it is not authentication or a global quota guarantee. Same-origin requests are accepted automatically. List any additional approved preview origins exactly in `CORS_ALLOWED_ORIGINS`; unrelated Vercel projects are rejected.

Configure the following **single** rule in the production project's Vercel Firewall, within the existing Hobby allowance. Inspect existing rules first; do not enable a paid feature or add a second rate-limiting rule:

| Field | Value |
| --- | --- |
| Name | JARVIS public API |
| Conditions (all) | Request method equals `POST`; request path starts with `/api/` |
| Action | Rate Limit |
| Strategy / counting key | Fixed window / IP |
| Window / limit | 60 seconds / 20 requests |
| Exceeded action | HTTP 429, without a JavaScript challenge |

Review and publish the rule in the dashboard, then verify the applied configuration and its traffic counters. This is account configuration and is **not enabled by deploying the repository**. The app retains bounded per-instance rate limits as a fallback; distributed abuse can still consume anonymous provider quotas. See [Vercel rate-limiting limits](https://vercel.com/docs/vercel-firewall/vercel-waf/rate-limiting).

The browser policy no longer permits inline scripts or general JavaScript evaluation in the application. The explicitly requested code runner has a separate opaque-origin sandbox and a no-network policy. HTML previews are inert. Keep the sandbox HTML/JS files and the matching CSP override together when deploying; the build includes them in the verified offline assets.

Public article requests validate DNS addresses at the connection boundary, revalidate redirects, and stop after a bounded response prefix. Remote Crawl4AI extraction is unavailable unless `CRAWL4AI_PUBLIC_EGRESS_VERIFIED=true` confirms that the renderer's own network blocks private addresses, redirects into private networks, and DNS rebinding. Merely setting this flag does not configure that network policy. Direct public HTML extraction remains available without Crawl4AI.

Diagnostics distinguish configured capabilities from runtime health. An enabled capability is not a successful provider health check. Temporary quota or service errors preserve feature entry points and drafts; retries remain manual for image generation. No prompts, source text, answers, or credentials should be sent to monitoring services by default.

## Vision credential troubleshooting

Check `/api/diagnostics` on the actual deployment (`https://jarvisjr.vercel.app/api/diagnostics` for the current production site). `model.groqConfigured`, `model.geminiConfigured`, and `vision.configured` indicate configuration presence; they do not validate credentials or provider quotas. The former chat fallback incorrectly reported missing keys after upstream failures even when both keys were configured. The corrected version reports the failure category and preserves an attempt for the second configured provider. Deploy the matching API changes as well as the frontend.

Refreshing or reopening now shows a fresh chat. Previous failed replies remain only inside their saved conversations, which can be opened from the sidebar; refreshing does not regenerate them. Once the corrected commit is deployed, reattach and retry the image in a new turn. No provider key should be copied into the browser, GitHub, or support messages.

Commit the person-photo modules (`app/person-photo-query.js`, `app/person-photos.js`, `api/_lib/person-photos.js`) with their changes to the existing search endpoint, visual resolver, rendering lifecycle, and styles. The lookup reuses `/api/search`; it adds no Vercel Function or paid service. Public image metadata is cached briefly, while image bytes load directly from Wikimedia. The optional lookup has a bounded timeout and never delays answer completion. Image dates are source capture dates, not upload timestamps. See [Commons structured search](https://commons.wikimedia.org/wiki/Help:Search) and [image metadata](https://www.mediawiki.org/wiki/API:Imageinfo).

The vision regressions exercise configured-model selection, Gemini-to-Groq fallback within the two-attempt limit, quota errors, ordinary scene recognition, and rejection of unconverted RAW/TIFF bytes. Browser checks also cover large-upload resizing, local uncommon-format conversion, and the centered model selector on laptop viewports. These mocked checks do not replace a real provider health check after deployment.
